# HbQt: Harbour's bindings for Qt

One binding layer, two levels, and the whole Qt API within reach of a .prg file.

HbQt wraps Qt the way Qt presents itself: it follows Qt's class hierarchy as is and encapsulates Qt objects the same way Qt does. For every Qt class there is a C++ wrapper named after the class (QWidget.cpp) and a matching PRG-level class prefixed with T (TQWidget.prg). The API you call from Harbour is the API the Qt documentation describes, so the Qt docs are the manual.

Signals and events connect straight to Harbour code blocks, and the binding covers two dozen Qt modules, from QtCore and QtGui to QtWebEngine, QtCharts and QtBluetooth, plus QScintilla for code editing and QZXing for barcodes.

/* A taste of HbQt, adapted from tests/signalslots.prg */
#include "hbqtgui.ch"

PROCEDURE Main()
   LOCAL oMain, oLabel, oScrollBar, oLayout, qApp

   oMain      := QWidget()
   oLayout    := QVBoxLayout()
   oScrollBar := QScrollBar()
   oLabel     := QLabel()

   oLabel:setText( "Move the slider" )
   oLayout:addWidget( oScrollBar )
   oLayout:addWidget( oLabel )
   hbqt_Connect( oScrollBar, "valueChanged(int)", oLabel, "setNum(int)" )

   oMain:setLayout( oLayout )
   oMain:show()

   qApp := QApplication()
   qApp:exec()
RETURN

Qt objects as Harbour objects. Signals connected in one line, layouts and widgets the Qt way, all in a .prg.

# The ecosystem around HbQt

The libraries and applications that ship in qtcontribs, all built on the same binding.

HbIDE

An integrated development environment for Harbour, written in Harbour itself. Code editor with syntax highlighting, a visual debugger, project management around hbmk2 .hbp files, find-in-files, themes, plugins, code skeletons and an integrated DBU panel. It is also the standing proof of how far a pure-Harbour HbQt application can go.

Static Windows builds on SourceForge

HbDBU

The classic DBU idea, rebuilt on Qt: open, browse and edit DBF tables, inspect structures, create tables, and work with your data outside your application. Selected builds add SQL access on top.

Static Windows builds on SourceForge

HbXBP

An Xbase Parts compatibility layer: Xbase++-style classes (Xbp* with the familiar appevent.ch event model) implemented on top of HbQt, giving Xbase++ GUI code a home in Harbour.

hbqtwidgets

A ready-made widget set written at the PRG level: data-aware browse grids, DBU panels, a syntax-highlighting editor, dashboards, charts, an on-screen keyboard, an icons manager, an HTTP client and common dialogs. The same pieces HbIDE is assembled from.

hbqtqmlparts

A bridge between Harbour and Qt Quick/QML, with ready parts for camera capture, barcode reading and embedded web views.

hbnetioqt

An HbQt management console for hbnetio servers: watch connected clients, manage addresses and terminate sessions from a desktop UI.

# History

Seventeen years of continuous development, and no commit lost along the way.

Mar 2009
HbQt's first commits land in the Harbour repository as contrib/hbqt, together with contrib/hbide and contrib/hbxbp.
Sep 2012
The Qt contribs move out of Harbour into a project of their own. qtcontribs opens on SourceForge and becomes their new home.
2013-2017
Steady releases: QtContribs setup packages and static HbIDE and HbDBU builds for Qt 4.8 through 5.9 with MinGW.
2023-2026
Active maintenance continues on SourceForge SVN, at revision 489 as of June 2026.
2026
The complete combined history, every commit by every contributor from March 2009 to today, is preserved in git at github.com/harbour-addons/qtcontribs.

# Get started

Two ways in: run a ready build, or build the whole tree yourself.

  1. Try it without a compiler. Download a static HbIDE or HbDBU build from SourceForge and run it. No Qt installation needed; everything is linked in.
  2. Set up a toolchain. You need Harbour 3.2 or later, a Qt development kit (Qt 4.8 or Qt 5.x) and a C++ compiler. Published kits pair MinGW with Qt, including a ready static Qt 5.8 build.
  3. Get the source. Check out the SVN tree at SourceForge or the git repository at github.com/harbour-addons/qtcontribs.
  4. Build. From the trunk, hbmk2 qtcontribs.hbp builds the libraries; each application has its own .hbp project, like hbide.hbp and hbdbu.hbp.
